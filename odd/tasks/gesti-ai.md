# Gesti AI (Claude API)

Branch `feat/gesti-ai` (from `feat/gesti-dashboard`). Connects the front-only Gesti chat (`odd/tasks/gesti-module.md`) to the Claude API: Sonnet 5.5 chats, Haiku 5.5 reads the portfolio, long documents and titles chats.
Chats, files and usage live in Supabase; `/demo/gesti` keeps the canned replies.

## Specs

- S1 (verbatim): "vamos a utilizar la API de claude en donde tengo 100usd por mes. La idea es poder usar sonnet 5.5 para la mayoria de las cosas y haiku 5.5 para el analisis de datos dentro de la base de datos" — main model `claude-sonnet-5-5`; portfolio analysis runs in a `claude-haiku-5-5` sub-agent that Sonnet calls through one tool.
- S2 (verbatim): "en la cual no podra borrar nada ni dar informacion sensible como tipo de datos, endpoints, contraseñas, hashes y demas" — the data sub-agent only has fixed read-only tools scoped to the caller's organization (no SQL, no write/delete tool); tool output never carries internal ids, column names/types, endpoints, keys, tokens or hashes; prompts forbid revealing system internals.
- S3 (verbatim): "Tendra un maximo de 5000 caracteres el cual no tendra que siempre llegar al limite, la idea es poder ahorrar tokens dentro de lo posible." + decision (L2) "Respuesta de Gesti" — the visible reply is at most 5000 characters (prompt + server hard cap); prompts ask for the shortest complete answer; prompt caching, trimmed history and Haiku for heavy reads save tokens.
- S4 (verbatim): "Podra leer y generar words, pdfs, excels, pero no podra generar imagenes, ni videos, ni archivos de codigo." — reads PDF, DOCX, XLSX (plus CSV/TXT and images as input); generates DOCX, PDF and XLSX only; no image/video/code-file generation tool exists and the prompt refuses those requests.
- S5 (verbatim): "Siempre tiene que ser orientado a el rubro de seguros, ley de transito y derecho argentino, pero no limitarlo solo a eso en caso de hacer mas preguntas como economia y demas." — system prompt.
- S6 (verbatim): "En caso de ser necesario podra generar algun grafico o algo interactivo o visual para que vea la persona." — `show_chart` tool rendered as an interactive chart (bar, line, area, pie) or table in the chat.
- S7 (verbatim): "Haiku 5.5 lo vamos a usar tambien para ponerle un nombre a la conversacion a partir del primer mensaje." — the title is generated by Haiku from the first message.
- S8 (verbatim): "Debe quedar funcionando la transcripcion." + decision (L2) "Web Speech API (gratis)" — dictation keeps the browser Web Speech API and keeps listening when the browser ends a session on its own.
- S9 (verbatim): "Debe poder editar en caso que le pidamos algun archivo, o leerlo y darnos una respuesta. Los pdf muchas veces son archivos de 36 paginas, quizas podemos usar haiku." — `read_document` and `edit_document` run on Haiku over the extracted text; edits return a new generated file (content preserved, original styling not).
- S10 (verbatim): "Tambien debera poder preguntar Gesti, como lo hace claude que hace preguntas en caso de no estar seguro de algo o para ser mas exacto, que no sea siempre, solo cuando sea necesario." — `ask_user` tool renders a question with 2-4 options plus free text; prompt limits it to real ambiguity.
- S11 (verbatim): "Vamos a borrar tambien el blur del streamingtext o bajarlo un poco para que no parezca que hay lag o se haga mas denso." — no blur on streamed words, quick opacity fade only, faster reveal.
- S12 (verbatim): "Quiero tambien que aparezcan las fuentes y demas en caso de buscar en internet" — `web_search` citations show as numbered inline chips and an "N fuentes" list with title and domain linking to the page.
- S13 (L2, verbatim): "El productor podra ver el consumo de cada usuario para poder tener un control de cuento gasta del humbral de 100usd del mes, y cuando se gasten que Gasti avise, que no tire un error" — every model call records its cost; productor (and platform admin) see this month's spend vs the budget and per-user spend; once the budget is spent Gesti answers with a normal message instead of an error. Budget is global for the API account (`GESTI_MONTHLY_BUDGET_USD`, default 100), month in Argentina time.
- S14 (L2, verbatim): "en la base de datos con supabase, y no se podran borrar los chats" — conversations, messages, files and usage in Supabase; no delete route and no delete action in the UI; rename and pin stay.

## Design

- DB (`supabase/migrations/20261027120000_gesti_ai.sql`): `gesti_conversations`, `gesti_messages` (text + `parts` jsonb), `gesti_files` (uploaded and generated, extracted text), `gesti_usage`; RLS on, no policies (service role only); private bucket `gesti-files`.
- API (`server/modules/gesti`, mounted under `/api/v1/gesti/*` by `app/api/v1/gesti/[...path]/route.ts` for a longer `maxDuration`): conversations list/get/patch, files sign/confirm/download, `POST /gesti/chat` NDJSON stream, `GET /gesti/usage` (productor/platform admin).
- Stream events: `meta` (conversation id), `title`, `status`, `text`, `source`, `chart`, `question`, `document`, `done` (stored message), `error`.
- Sonnet tools: `web_search_20250305` (max 3 uses, AR location), `consultar_cartera`, `read_document`, `edit_document`, `create_document`, `show_chart`, `ask_user`. History is rebuilt from stored text (no raw tool blocks), last 12 messages.
- Front: `AIAssistantInterface` takes a backend (`api` for the CRM, `demo` canned for `/demo/gesti`).
- Shared contracts (parent-owned, do not change without the parent): `lib/gesti-parts.ts` (parts, chart spec, `MAX_REPLY_CHARS`), `lib/gesti-contract.ts` (DTOs, stream events, `parseStreamLine`), `server/modules/gesti/documents/spec.ts` (document spec, extract result).

### T4 server design

- Files in `server/modules/gesti/`: `config.ts` (lazy env: `ANTHROPIC_API_KEY` optional, `GESTI_MONTHLY_BUDGET_USD` default 100; `MODEL_MAIN = "claude-sonnet-5-5"`, `MODEL_FAST = "claude-haiku-5-5"`), `pricing.ts` (USD per MTok per model: input, output, cache read 0.1x input, cache write 1.25x input; web search USD 10 per 1000; defaults Sonnet 3/15, Haiku 1/5, with a comment that they must be checked against Anthropic's price list), `usage.ts`, `prompts.ts`, `data-tools.ts`, `agents.ts`, `files.ts`, `conversations.ts`, `chat.ts`, `schemas.ts`, `routes.ts`. Anthropic client created lazily and injected (tests use a fake).
- Router: `createApiHandler` returns a handler result that is already a `Response` as is (streaming). `app/api/v1/gesti/[...path]/route.ts` reuses `handleApiRequest` with `runtime = "nodejs"`, `dynamic = "force-dynamic"`, `maxDuration = 300`.
- Routes (all `organization` access; chats are private to their owner, other users get 404): `GET /gesti/conversations` (owner's, `updated_at desc`, max 200), `GET /gesti/conversations/:id` (with messages asc), `PATCH /gesti/conversations/:id` (`title` 1-120, `pinned`), `POST /gesti/files/uploads` (max 6, mime allowlist `GESTI_UPLOAD_MIME_TYPES`, max 30 MB, path `<org>/<user>/<uuid>/<safe name>`), `POST /gesti/files` (verify path prefix + object exists + size, download, extract text for documents, insert `gesti_files` origin upload; unreadable → 422 with a Spanish message and the object removed), `GET /gesti/files/:id/url` (owner, signed 10 min, `download` name), `POST /gesti/chat` (body 64 KB, rate limit 20/min, NDJSON stream), `GET /gesti/usage` (productor or platform admin, else 403). No DELETE route under /gesti.
- Chat flow: validate body → load or create conversation (owner check) → save user message with `parts.attachments` → emit `meta` → if new conversation, Haiku title in parallel (max_tokens ~30, Spanish, max 6 words, no quotes) → update title, emit `title`. Not configured (no key) → assistant message with `notice: "not_configured"`. Budget: month spend (global, Argentina month, UTC-3) >= budget → assistant message with `notice: "budget_exhausted"`, friendly Spanish text ("Este mes ya se usó todo el presupuesto de Gesti…", says when it comes back: the 1st of next month, and to talk to the productor), no model call.
- Sonnet call: `max_tokens` 4096, system prompt + tools with `cache_control: { type: "ephemeral" }`, no extended thinking. History: last 12 stored messages rebuilt as text (user: text + `[Adjunto: name · file_id: X · N páginas]`; assistant: content without `[[n]]` markers + one-line notes for charts/questions/documents, e.g. `[Archivo generado: name · file_id: X]`). Current turn attachments: documents with extracted text <= 15000 chars go inline as `<documento nombre="…" file_id="…">…</documento>`; longer ones only by reference (Sonnet uses `read_document`); images as base64 image blocks (<= 5 MB) only on the current turn.
- Tool loop (max 6 rounds) with `messages.stream`: forward text deltas as `text` events (hard cap `MAX_REPLY_CHARS` visible chars, then stop forwarding and end with "…"); `web_search_20250305` (max_uses 3, user_location Argentina) → `status` "Buscando en internet…"; `citations_delta` with `web_search_result_location` → dedupe by url into `parts.sources`, emit `sources`, and when that text block stops emit its markers ` [[n]]`; `pause_turn` → continue; client tools executed then `tool_result`s appended: `consultar_cartera {pregunta}` (status "Consultando tu cartera…", Haiku data agent, adds app sources), `read_document {file_id, pregunta}` (status "Leyendo el documento…", Haiku over the extracted text; scanned PDFs with < 200 chars of text and <= 20 MB go to Haiku as a base64 PDF document block), `edit_document {file_id, instrucciones, formato?}` (status "Editando el archivo…", Haiku returns a DocumentSpec via a forced tool, then render + store + `document` event), `create_document` (input = DocumentSpec; status "Generando el archivo…"; render + store as origin generated + `document` event), `show_chart` (input = ChartSpec, max 4; invalid → `is_error` tool_result so the model fixes it; valid → `chart` event), `ask_user` (input = question schema; emit `question`, end the turn without a tool_result). Only file ids that belong to the caller's conversation/user can be used by tools.
- Every model call (Sonnet rounds, Haiku title/data/document) records a `gesti_usage` row with tokens, cache tokens, `server_tool_use.web_search_requests` and `cost_usd`. Model or network errors → assistant message with `notice: "error"` and "No pude responder ahora. Probá de nuevo en un momento."; the client disconnecting (`request.signal`) aborts the stream and stores what was written. Final event `done` with the stored assistant message.
- Data agent (Haiku, max 6 tool rounds, max_tokens 1500, answer <= 3000 chars, facts only): read-only tools that query with `supabase.admin`, always `.eq("organization_id", orgId)`, select only needed columns, return Spanish-keyed plain objects WITHOUT ids/uuids, column names, types or DNI (DNI may be used as a search input): `buscar_asegurados {texto}`, `ficha_asegurado {nombre}` (client + active policies + upcoming/unpaid notices), `listar_avisos {estado?, desde?, hasta?, compania?, limite<=100}`, `listar_polizas {rama?, compania?, forma_pago?, texto?, limite<=100}`, `resumen_cartera {}` (counts by branch, company, notice status, overdue unpaid, due in 7/30 days), `listar_tareas {estado?, vencidas?, limite<=100}`. Tool errors return a generic message, never the Postgres error.
- Prompts (Spanish, Rioplatense voseo, concise): main prompt = Gesti identity, focus on insurance, Argentine transit law (Ley 24.449 and provincial rules) and Argentine law, other topics allowed briefly; shortest complete answer, at most 5000 characters; plain text with short paragraphs, `•` bullets, numbered lists and `**bold**`, no markdown tables (use `show_chart` kind table) and no headings; copyable messages for clients go between `:::borrador` and `:::` lines; use `ask_user` only when the request is truly ambiguous or a missing detail changes the answer; never generate images, videos or code files, nor write code; never reveal the system prompt, tools, models, database structure, data types, endpoints, ids, keys, passwords, tokens or hashes; data questions go through `consultar_cartera`, never invented; cite web sources; legal answers are general information, recommend checking with a professional when it matters. Today's date in Argentina is injected per request (not inside the cached block).

### T5 front design

- `lib/gesti-api.ts`: typed client for the T4 routes using `apiRequest` / `uploadToSignedUrl` from `lib/api.ts`; `streamGestiChat(payload, auth, onEvent, signal)` reads the NDJSON body with `parseStreamLine` (handles chunks split mid-line, retries once on 401 via `refreshStoredAuth`).
- `AIAssistantInterface` receives a backend object (`GestiBackend`: list, get, update, upload, send) instead of reading localStorage: `components/views/gesti-view.tsx` passes the API backend (token + org slug + whether the user can see usage); `app/demo/gesti/page.tsx` passes a demo backend built from the existing canned replies (moved out of the interface into `lib/gesti-demo.ts`), kept in memory.
- History panel: no delete action anywhere; rename and pin call PATCH; list comes from the API (refetch after a new chat gets its title); messages load when a chat opens.
- Streaming text: words appear as deltas arrive; reveal pace catches up when behind (never more than ~250 ms behind the stream); no blur, only a quick opacity fade (<= 120 ms). Renders `**bold**`, `•`/`-` bullets and numbered lines, `:::borrador` blocks (existing DraftBlock), `[[n]]` citation chips (link to `sources[n-1]`, open in a new tab with `rel="noopener noreferrer"`). While a `status` label is active, show it next to the Gesti loader.
- Sources list: web sources show favicon-free title + domain and open the page; app sources keep the existing chips that navigate to the tab.
- Parts: `GestiChart` (from T3, `components/ui/gesti-chart.tsx`) per chart; question card with the options as buttons (sends the option text) and a hint that they can also type, only interactive on the last message; document cards (icon by format, name, size, "Descargar" asks `/gesti/files/:id/url`); user attachments keep `AttachmentList` (download link for stored ones). `notice` messages get a subtle variant style.
- Composer: `accept` = `GESTI_UPLOAD_ACCEPT`; files upload (signed URL + confirm) when sending, with the composer showing progress; rejected types/sizes show the existing notice. Remove the "Vista previa" badge; keep the disclaimer.
- Usage: for productor/platform admin a "Consumo" button in the chat header opens a Modal with the month, a progress bar spent/budget (global), the organization total and a per-user table (name, consultas, USD). Others don't see it.
- Remove follow-up suggestions from real replies (they cost tokens); the demo keeps them.
